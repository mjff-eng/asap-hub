Handle a Contentful migration for ASAP Hub: $ARGUMENTS

The first word says which space (`crn` or `gp2`); the rest describes the migration. If the space is missing, infer it from context or ask.

Workflow:
1. Create the migration with `yarn contentful:migration:create:crn` or `yarn contentful:migration:create:gp2`, then implement the migration logic in the generated file. Look at recent migrations in the repo for the established patterns (field creation order, displayField changes before deleteField, etc.).
2. Validate with the corresponding `dryrun` script before ever suggesting `run`. Show me the dryrun output.
3. Do NOT execute the real `run` against Contentful unless I explicitly say so — creating and dry-running is the default scope of this command. Mention the exact `run` and `rollback-migration` commands I'd use.
4. After a migration that changes the schema, refresh generated types: `yarn contentful:schema:update` and regenerate the autogenerated GraphQL. If live-space credentials aren't available, use the offline path: hand-edit the committed schema file, run local codegen, then prettier over the output.
5. If the migration touches content types used by both analytics and app code, flag downstream places that may need matching changes (data-providers, GraphQL queries, model types).
